# 6. Race Condition là gì?

Có thể hiểu:

> **Race condition xảy ra khi kết quả phụ thuộc vào thời điểm hoặc thứ tự mà nhiều thao tác đồng thời xảy ra.**

Timeline:

```text
Client A              Client B

READ                   READ
slot free              slot free

DECIDE                 DECIDE
can book               can book

WRITE                  WRITE
booking A              booking B
```

Một client riêng lẻ có thể chạy đúng.

Nhưng nhiều client cùng chạy thì hệ thống sai.

---

# 7. Vì sao `check → write` bằng hai lệnh riêng vẫn chưa an toàn?

Một cách tưởng đúng:

```tsx
const snap =
  await getDoc(bookingRef);

if (!snap.exists()) {
  await setDoc(
    bookingRef,
    bookingData
  );
}
```

Nhưng vẫn có khoảng thời gian giữa:

```text
READ
```

và:

```text
WRITE
```

Hai client có thể cùng đọc trước khi một client kịp ghi.

Kết luận:

> **READ → CHECK → WRITE phải được bảo vệ như một transaction, không phải ba thao tác độc lập.**

# 20. `handleBookRoom()` sau khi hoàn thành Core Week 8

Đối chiếu với code của bạn:

```tsx
async function handleBookRoom() {
  setMessage("");

  if (!selectedRoom) {
    setMessage(
      "Please select a room."
    );
    return;
  }

  if (!selectedSlot) {
    setMessage(
      "Please select a time slot."
    );
    return;
  }

  if (!purpose.trim()) {
    setMessage(
      "Please enter purpose."
    );
    return;
  }

  if (!bookedBy.trim()) {
    setMessage(
      "Please enter your name."
    );
    return;
  }

  const slotKey =
    toSlotKey(selectedSlot);

  const bookingId =
    `${selectedRoom.id}_${slotKey}`;

  const bookingRef =
    doc(
      db,
      "bookings",
      bookingId
    );

  try {
    await runTransaction(
      db,
      async (transaction) => {
        const bookingSnap =
          await transaction.get(
            bookingRef
          );

        if (
          bookingSnap.exists()
        ) {
          throw new Error(
            "SLOT_ALREADY_BOOKED"
          );
        }

        transaction.set(
          bookingRef,
          {
            roomId:
              selectedRoom.id,

            roomName:
              selectedRoom.name,

            building:
              selectedRoom.building,

            slot:
              selectedSlot,

            purpose:
              purpose.trim(),

            bookedBy:
              bookedBy.trim(),

            createdAt:
              serverTimestamp(),
          }
        );
      }
    );

    setMessage(
      "Booking successful."
    );

    setPurpose("");
    setBookedBy("");
  } catch (error) {
    if (
      error instanceof Error
      && error.message
        === "SLOT_ALREADY_BOOKED"
    ) {
      setMessage(
        "Slot already booked."
      );
      return;
    }

    console.error(
      "Booking transaction failed:",
      error
    );

    setMessage(
      "Booking failed. Please try again."
    );
  }
}
```

# 23. Transaction callback có thể chạy lại

Tình huống:

```text
Client A transaction
READ: document missing

Client B transaction
READ: document missing

A commits first
→ document changes

B đã đọc version cũ
→ Firestore detects conflict
→ transaction callback B có thể retry

B READ again
→ document exists
→ SLOT_ALREADY_BOOKED
```

Không cần tự viết vòng lặp retry.
